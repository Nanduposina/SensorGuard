# SensorGuard resume-claim audit

## Scope and evidence standard

This audit checks the four proposed resume bullets against source code, tests, generated output and the official [Intel Berkeley Research Lab dataset documentation](https://db.csail.mit.edu/labdata/labdata.html). “Verified” means evidence supports the exact wording at the stated scope. Synthetic fault results do not establish historical accuracy. No inferred or unlabeled reading is treated as a confirmed negative.

The official documentation describes a 54-mote deployment, per-mote epoch sequences, potentially missing or truncated data, and a strong relationship between voltage and temperature. The local source contains additional IDs, so the observed ID count is not forced to 54.

## Reproduction and measured results

- Working tree at audit start: `main` at `d63eb4961e6917ed8134671a6615f799ad0b83d1`, matching `origin/main`; one unrelated untracked user file, `sensorguard_filtered_alerts.csv`, was preserved.
- The previous demo path `artifacts/resume-claim-audit-20261027` already contained a profile and complete experiment outputs but no review database. It was not overwritten. A new run used `artifacts/resume-claim-audit-20261027-rerun` and `.sensorguard/resume-claim-audit-20261027-rerun.sqlite3`.
- A new Python 3.12.10 environment installed `.[dev,dashboard]` and passed `pip check`; on execution, Windows Application Control blocked a pandas native DLL from that temporary environment. No global packages were changed. The demo was rerun with the pre-existing `.venv` (Python 3.12.10), whose `pip check` and CLI help succeeded.
- Profiling completed in 37.21 seconds: 2,313,682 rows, 61 IDs, and zero repeated timestamp/sensor keys. The full profile is in the ignored run output. It reports 526 blank-ID trailing rows, missing measurements, plausibility screenings, ordering reversals and gaps; it does not claim the blank suffix is corruption.
- Bounded experiment: seed 42; 386 sampled records; chronological split 231/77/78; 3 injected fault events; 11 known positive feature-reading pairs; 390 evaluated feature-reading pairs; 379 unlabeled pairs. Injected-positive recall: rules 11/11 (1.00), Isolation Forest 6/11 (0.545), autoencoder 6/11 (0.545), combined rules + Isolation Forest + autoencoder 11/11 (1.00). These recall values are limited to the selected artificial faults. Alerts on unlabeled pairs were 80 (rules), 98 (Isolation Forest), 93 (autoencoder), and 185 (combined); these are not false positives because the unlabeled pairs are not verified normal. The full experiment report contains detector breakdowns.
- Streamlit served at `http://localhost:8504`; `/_stcore/health` returned `ok`. AppTest checked Overview, Sensor explorer, Alert investigation, Alert review, Model evaluation, and Sensor health against generated artifacts. A generated review was saved and updated, then exported and imported into a separate database successfully. The long-running demo was stopped after verification; its final process exit was 1 because the server was interrupted intentionally, not because the profiler or experiment failed. The temporary-environment demo attempt separately exited 1 before profiling due the Windows Application Control DLL block.
- No independently documented historical battery-failure examples, battery replacement records, or verified labels were found in the repository or official dataset documentation. Historical voltage trends remain candidates; temperature correlation and other sensor/environment effects are alternative explanations.

## Preservation and release status

The original raw dataset, pre-existing CSV, original `.venv`, existing `.sensorguard/reviews.sqlite3`, and prior artifact directories were not modified. New demo outputs and the new review store are ignored local artifacts. Only README, demo-script, test, and this audit-document changes are intended for review; the unrelated CSV is not to be staged.

This report records the audit evidence; the release commit, pushed branch, and hosted Actions result are reported separately so they can be tied to the exact resulting commit SHA.
